# 修复说明（逐条对应实机四个问题）

所有结论都来自本机固件/镜像本身，证据路径写在每一条后面。

---

## 1. 无法挂载所有分区

### 现象对应的真实原因

| # | 原因 | 证据 |
| --- | --- | --- |
| 1 | 动态分区没有 map，`/dev/block/mapper/*` 不存在 | 原 `BoardConfig.mk` 里没有 `TW_INCLUDE_LOGICAL`；旧 `recovery.fstab` 里 `/system ... system ... logical` 只是写了 `logical`，缺编译开关时 TWRP 直接跳过 |
| 2 | fstab 的 logical 条目设备列写的是裸名 `system`/`vendor`/… | 旧 `system/etc/recovery.fstab`（1350 B，就是被刷进 ramdisk 的那份） |
| 3 | 写了本机不存在的分区 | 真机 super 元数据里只有 `system / vendor / product / system_ext`，**没有 odm**；本机也没有 SD 卡槽（`/dev/block/mmcblk1p1` 永远不存在） |
| 4 | `/dev/block/bootdevice` 靠 `on fs` 里 `wait` + `symlink` 建，一旦属性缺失/时机不对，所有物理分区路径全失效；`/dev/block/by-name` 则完全没人建 | 旧 `init.recovery.qcom.rc` 只有 bootdevice 一条链接 |

### 真机实际布局（这次直接以它为准）

`1.img`（4 GiB，super 整盘 dump）解析结果：

```
lp metadata v10.0  max_size=65536 slots=2 logical_block_size=4096
block device: super, first_logical_sector=2048, size=4294967296
group qti_dynamic_partitions  max_size=4294967296        <-- 不是 qualcomm_dynamic_partitions
system      2355560448 B (2246.4 MiB)
vendor       921370624 B ( 878.7 MiB)
product       76292096 B (  72.8 MiB)
system_ext    95432704 B (  91.0 MiB)                    <-- 没有 odm
```

GPT（`gpt_main0.bin`）关键项：

```
boot      65536 sectors = 32 MiB      <-- 原树写的 64 MiB 是错的
recovery 131072 sectors = 64 MiB
super   8388608 sectors = 4 GiB
metadata  32768 sectors = 16 MiB
userdata        剩余全部
```

### 本版做法

* `BoardConfig.mk`：`TW_INCLUDE_LOGICAL := true`，分区尺寸按 GPT 修正，super 组名改成
  `qti_dynamic_partitions`，分区列表 `system system_ext vendor product`。
* `recovery/root/system/etc/twrp.fstab`：dynamic 分区用
  `/dev/block/mapper/<name>` + `logical`；物理分区统一 `/dev/block/bootdevice/by-name/*`；
  删掉 odm / sdcard，补上 `/super`、`/persist`。
* `recovery/root/init.recovery.qcom.rc`：`on fs` 里同时建
  `/dev/block/bootdevice` 和 `/dev/block/by-name` 两个链接（后者 fastbootd 要用）。

## 2. /data 解密：不需要（本机 userdata 默认不加密）

原树没编 crypto（镜像 binary 里能直接搜到
`no_crypto_support=No crypto support was compiled into this build.`），
但实机上 userdata 默认就是未加密的：原厂 fstab 里的
`fileencryption=aes-256-xts:aes-256-cts:v2+emmc_optimized+wrappedkey_v0`
在这台机器上没有真正生效，所以这条不用修，也不需要 vendor keymaster/gatekeeper。

本版处理：

* `TW_INCLUDE_CRYPTO` / `TW_INCLUDE_CRYPTO_FBE` / `TW_INCLUDE_FBE_METADATA_DECRYPT`
  全部保持注释（以后换加密 ROM 再打开）。
* 删掉之前为解密准备的 vendor keymaster/gatekeeper 服务与依赖库、
  `init.recovery.qcom_decrypt.rc`、`vendor/etc/vintf/manifest.xml`。
* `twrp.fstab` 与 `recovery.fstab` 的 `/data` 去掉 `fileencryption=`，
  `/metadata` 去掉 `wrappedkey`，`/data` 直接挂 f2fs。
* 同时也就去掉了 TWRP 启动阶段跟 keymaster 交互的那一段，少一个卡启动画面的因素。

## 3. fastbootd 不正常

### 原因

* 原 `BoardConfig.mk` 没有 `TW_INCLUDE_FASTBOOTD`：
  Reboot 菜单里不会出现 Fastboot（主题里该按钮条件是 `tw_fastboot_mode=1`），
  TWRP 也不会去设 `sys.usb.config=fastboot`。
* TWRP 的 `init.rc` 里 `service fastbootd /system/bin/fastbootd` 是 `disabled` 的，
  只由 `on property:sys.usb.config=fastboot` 拉起 —— 上面没设属性，服务永远不启动。
* 即使拉起来，fastbootd 还需要：
  - fs_mgr 格式的 `/etc/recovery.fstab`（原树只有 TWRP v2 格式，字段含义不同）；
  - `/dev/block/by-name/super`（AOSP fastbootd 硬编码这个路径找 super）；
  - `ro.boot.dynamic_partitions=true`（stock 是在 build_default.prop 里写死的，TWRP 只能从 cmdline 拿）。

### 本版做法

* `TW_INCLUDE_FASTBOOTD := true`。
* `recovery/root/system/etc/recovery.fstab` 改成 fs_mgr 格式（logical 分区 + `first_stage_mount`、
  `/data` 保留原厂 `fileencryption=`）。
* init rc 建 `/dev/block/by-name → …/by-name` 链接。
* cmdline 追加 `androidboot.dynamic_partitions=true`。

## 4. 进不了 EDL

### 原因

* 主题里 EDL 按钮的条件是 `tw_edl_mode=1`，它由 BoardConfig 的 `TW_HAS_EDL_MODE` 决定；
  原树没有这个开关 → 按钮直接不显示，用户没有入口。
* Download 项同理，由 `TW_HAS_DOWNLOAD_MODE` 控制。

### 本版做法

* `TW_HAS_EDL_MODE := true`、`TW_HAS_DOWNLOAD_MODE := true`。
* 提供 `/system/bin/rebootedl.sh` 作为兜底（TWRP 的 reboot 实现会优先执行
  `/system/bin/rebootedl.sh`，其次才是 `reboot,edl` / `reboot edl`）。

ABL 侧是有 EDL 分支的（`abl_fv.bin` 字符串：
`Failed to WriteRecoveryMessageEdl`、`Boot reason: 0x%x not handled`），
所以 `sys.powerctl=reboot,edl` 这条内核 restart reason 能被 bootloader 识别。
真进不去时，硬件短接/按键组合进 9008 永远可用，GeekFlashTool 读回也是这条路。

## 5. adb / MTP 都用不了

### 原因

`abl_fv.bin` 里能看到的 cmdline 注入项只有 `androidboot.bootdevice`、`boot_devices`、
`chipid`、`mode`、`serialno` 等，**没有 `androidboot.usbcontroller`**。
于是：

```
ro.boot.usbcontroller  →  空
sys.usb.controller     →  没人设（stock init.recovery.qcom.rc 只在
                          on property:ro.boot.usbcontroller=* 里设置，该触发器永不执行）
```

而 TWRP 的 configfs 触发器全部是这个形状：

```
on property:sys.usb.config=adb && property:sys.usb.ffs.ready=1 && property:sys.usb.configfs=1
    ...
    write /config/usb_gadget/g1/UDC ${sys.usb.controller}     <-- 写空值，直接失败
```

UDC 从没被写入过 → gadget 没有绑定到控制器 → PC 端连设备枚举都看不到，
adb、MTP、fastbootd 的 USB 一起失效（这也是"adb 和 mtp 同时不能用"的唯一解释）。

第二个独立问题：TWRP 自带的 `init.recovery.usb.rc` 只有 legacy
`/sys/class/android_usb/android0/...` 写法，且只在那里有一条 `sys.usb.config=mtp,adb`；
本机是 configfs + `vendor.usb.use_ffs_mtp=1`，MTP 要靠 `ffs.mtp` functionfs 实例，
TWRP 默认 rc 里根本没有，所以即使 adb 通了 MTP 也不会通。

### 本版做法

* `init.recovery.qcom.rc` 的 `on init` 里写死：

```
setprop sys.usb.controller 4e00000.dwc3
```

  DT 里 USB 控制器节点是 `dwc3@4e00000`，configfs UDC 名即 `4e00000.dwc3`。
* `TW_EXCLUDE_DEFAULT_USB_INIT := true`，用设备树自己的
  `recovery/root/init.recovery.usb.rc` 取代 TWRP 那份 legacy 的，内容包含：
  - `on fs` 建 gadget、建 `ffs.adb` / `ffs.mtp` / `ffs.fastboot` 三个 function，
    挂 functionfs 到 `/dev/usb-ffs/{adb,mtp,fastboot}`；
  - `adb`、`mtp`、`mtp,adb`、`fastboot`、`sideload`、`none` 六套 configfs 触发器
    （每次都先 `UDC "none"` + 清 f1/f2，避免切配置时 symlink 冲突）；
  - MTP 走 `sys.usb.ffs.mtp.ready`（TWRP 的 MTP 服务就绪时置位）再绑定，
    避免 functionfs 未就绪就 bind 导致枚举失败；
  - `on boot` 再兜底 bind 一次。

## 6. /system、/vendor 挂载报 Invalid argument（shared_blocks）

### 原因（真机上验证过）

四个 super 逻辑分区都是 ext4 且带 `shared_blocks`（去重共享块，系统镜像常见）：

```
tune2fs -l /dev/block/dm-0
Filesystem features: ... shared_blocks        <- system
Filesystem features: ... shared_blocks        <- vendor / product / system_ext 同样
```

带这个特性的 ext4 **不允许读写挂载**，内核直接返回 `EINVAL`：

```
mount -t ext4 -o ro /dev/block/dm-0 /mnt/t1 -> RC=0      只读可以
mount -t ext4 -o rw /dev/block/dm-0 /mnt/t2 -> Invalid argument
```

TWRP 默认按读写去挂，所以日志里是：

```
Failed to mount '/system_root' (Invalid argument)
Failed to mount '/vendor' (Invalid argument)
```

而且 TWRP 主题里“挂载 System 为只读”那个勾选框只对非 super 设备显示
（条件是 `tw_is_super=0`），本机 `tw_is_super=1`，界面上没有这个开关可用。

### 本版做法

`twrp.fstab` 里给这四个分区加 `fsflags=ro`，让 TWRP 直接用只读挂载：

```
/system_root  ext4  /dev/block/mapper/system   flags=display="System";logical;backup=1;fsflags=ro
/system_ext   ext4  /dev/block/mapper/system_ext ... ;fsflags=ro
/vendor       ext4  /dev/block/mapper/vendor  ... ;fsflags=ro
/product      ext4  /dev/block/mapper/product ... ;fsflags=ro
```

挂上之后真实系统在 `/system_root/system`（本机是 system-as-root 布局，
分区根目录下才有 system/vendor/product 子目录），TWRP 文件管理器进 `/system_root` 就能看到。

想改成可写（刷 system 级 Magisk 之类）必须先 `e2fsck -E unshare_blocks /dev/block/dm-0`
把共享块展开，且 system 只剩 86 MB 空闲，风险较大，不建议。
